### Web dashboard
- Launch (double-click): `start-second-brain.bat` at repo root - starts the dev server if not already up, waits for readiness, opens the default browser to http://localhost:3000. The "Second Brain" desktop shortcut points to it.
- **The Diagnostics page says what code is running (2026-09-16).** A "Deployment" card at the top of `/settings`: the commit this server is on, its subject and age, a warning when uncommitted changes are blocking automatic updates, and the updater's last checkpoint from `.claude/data/logs/update.log`. It **reports, never asserts**, like the app registry - it does not fetch (a page render must not wait on the network) and never claims `SecondBrain-Update` is registered, because from here that cannot be verified; a missing log says the updater has never run rather than implying it is fine. `src/lib/services/deployment.ts` shells out to `git` only, no PowerShell, so the card works on a laptop too.
- **Supervised host recovery (2026-08-10):** `.claude/scripts/setup_web_host.ps1` owns three per-user tasks that are deliberately separate from the opt-in agent scheduler: `SecondBrain-WebHost` starts the browserless `npm run dev` host at logon and Task Scheduler restarts it on process exit; `SecondBrain-WebWatchdog` requires the G2-specific `/api/health` marker and requests recovery only after three consecutive two-minute failures; `SecondBrain-WebRecover` stops/relaunches the task and refuses to terminate any orphan port-3000 listener unless its Node command line proves it belongs to this repo. `recover-g2.bat` is the independent SSH/manual entry point, and the existing desktop launcher now delegates to the recovery task when installed instead of racing a stale listener with another dev server. `-Status` reports task plus HTTP health, `-Recover` triggers a clean restart, and `-Remove` affects only these three tasks. Runtime state/logs stay ignored under `.claude/data/`. The tasks were registered and a stale pre-existing listener plus a second scheduled restart were both recovered live before handoff. Do not merge these names into `setup_scheduler.ps1`: its no-flags mode intentionally removes agent automation, while dashboard uptime must remain on. See `docs/DEPLOYMENT.md`.
- **Remote access (Tailscale):** the dashboard is reachable from the owner's tailnet at `https://your-machine.your-tailnet.ts.net/`; Tailscale Serve routes `/` to port 3000 so the browser has a trusted HTTPS origin. Since 2026-09-22 `npm run dev` binds `127.0.0.1` only, so direct tailnet HTTP (`http://your-machine:3000`) no longer works - use the `https://` Serve URL from every device. Before that, `next dev` defaulted to all interfaces, and with node allowed inbound on the Public firewall profile and auth off, the dashboard was reachable from the campus Wi-Fi with no login; `sec.host_config` now checks the live binding weekly. `dev:remote` (`-H 0.0.0.0`) is the explicit, deliberate exception; do not make it the default. Known risk: Tailscale's auto-update silently uninstalled itself on 2026-07-23 and killed remote access with no notice; `tailscale set --auto-update=false` was offered but not applied (trade-off: loses automatic security patches). The personal deployment relies on Tailscale identity and `src/middleware.ts` leaves dashboard Basic auth disabled by default, so localhost and tailnet access have no second prompt. Set `DASHBOARD_AUTH_ENABLED=true` to require HTTP Basic user `g2` with `OPS_API_TOKEN` (or the capture-token fallback) on every host. Mutating API routes independently keep their same-origin/bearer checks in `src/lib/auth.ts`.
- `npm run dev` - dev server (Node lives at `%LOCALAPPDATA%\Programs\nodejs`; prefix `$env:Path = "$env:LOCALAPPDATA\Programs\nodejs;$env:Path"` if `node` doesn't resolve)
- `npm run build` / `npm run lint` / `npm run typecheck` - build / lint / type-check
- `npm test` - the TypeScript unit tests (`src/**/*.test.ts`, Node's built-in runner through `tsx`). Put pure service math under the same convention rather than asserting on source strings from Python.
- `npm run db:push` (apply schema) / `npm run db:seed` / `npm run db:reset` - Prisma SQLite DB; `npx prisma studio` to inspect

### Agent system
- Memory flush test: `python .claude/scripts/memory_flush.py --test` - exercise the flush pipeline end to end
- Hook/flush logs: `.claude/data/logs/hooks.log` and `flush.log`
- Memory index: `python .claude/scripts/memory_index.py` (incremental; `--rebuild` from scratch, `--stats` to inspect). **Embeddings are `bge-m3` via Ollama (1024-dim, multilingual) as of 2026-07-25** - migrated off FastEmbed all-MiniLM-L6-v2 (384-dim, English-only) because the owner works in Korean and English. FastEmbed remains an automatic fallback if Ollama is down, but it has a different dimension, so switching backends requires `--rebuild`. Indexes `G2OS-Staging/`, `Research-Private/`, `Memory/`; excludes `Finance/`, `Confidential/`, and `archive/`.
- Memory search: `python .claude/scripts/memory_search.py "<query>" [--k N] [--path-prefix Memory/drafts/sent] [--json]`
- Integration status: `python .claude/scripts/query.py status`
- Integration queries: `python .claude/scripts/query.py <gmail|calendar|drive|papers|slack|github> <subcommand> [--json]` (e.g. `gmail admin` for unread + read-independent self-forwarded intake, `gmail draft <to> <subj> <body_file>`, `calendar upcoming 48`, `drive list`, `papers new`, `papers search "<phrase>"`, `slack needs-response`, `slack since [days] [--all]` + `slack mark-scanned [ts]` (incremental catch-up: `since` pulls messages newer than the on-disk checkpoint at `.claude/data/state/slack-scan-state.json` - DMs+group-DMs by default, add `--all` to also sweep channels but it's slow due to Slack history rate limits; `mark-scanned` advances the checkpoint after drafting; used by the `draft-replies` skill's Slack catch-up mode; `slack-catchup` is its alias), `github notifications`, `github assigned`, `github reviews`)
- Reply drafting (on-demand): the `draft-replies` skill (`/draft-replies`) scans Gmail + Slack (via query.py) + Outlook (via M365 MCP, when reachable) and writes drafts to `VAULT/Memory/drafts/active/`. Runs interactively (uses this session's auth, so it works even if the .env ANTHROPIC_API_KEY is invalid).
- Background reasoning model: `AGENT_MODEL` in shared.py (env `SECONDBRAIN_MODEL`, default `sonnet`) - applied to flush, guardrail, heartbeat, reflection. Sonnet per the owner (cost).
- Dashboard **"Check messages & calendar"** button: `/ops` "Capture automation" card (it was on Today's "Needs you" panel until that card was removed 2026-08-27) -> `POST /api/secondbrain/heartbeat` -> spawns `agent_day.py --team admin --force` (SECONDBRAIN_PYTHON, miniconda). It scans Gmail and every new one-to-one Slack DM independent of Slack read state, then drains reply jobs; **no API key needed** because Claude runs on the subscription CLI. Distinct from **"Process captures"**, which runs the vault team over material already captured.
- Folded reflection: `heartbeat.maybe_reflect()` runs `memory_reflect.py` once per calendar day (tracked by `reflection_date` in heartbeat-state.json), so the scan button also consolidates yesterday's daily log into MEMORY.md - no separate scheduled reflection needed. Repeated same-day clicks skip it (no extra tokens).
- `slack unread [days]`: all unread incoming across DMs+channels (newer than read-marker); `slack needs-response` is the narrow DM/mention view.
- OAuth/token setup: `python .claude/scripts/setup_auth.py google` (see docs/INTEGRATIONS_SETUP.md)
- Wiki build: `python .claude/scripts/wiki_build.py` - maintains the cross-linked LLM Wiki at `VAULT/Memory/wiki/` (see the `wiki` skill)
- Subscription limits: `python .claude/scripts/usage_limits.py [--json] [--no-write]` - remaining Claude + Codex capacity and reset times; refreshes `.claude/data/state/usage-limits.json`, which the header usage board reads. Emits percentages only, never the token.
- Usage ledger: `python .claude/scripts/usage_ledger.py summary` (month-to-date totals) / `seed` (demo rows, gitignored) / `clear`. Ledger at `.claude/data/usage.jsonl`; other tools append rows in the same JSON shape to track cross-provider spend. Surfaced by the Home `UsagePanel`.
- Heartbeat: `python .claude/scripts/heartbeat.py` (`--force` ignores active hours, `--dry-run` stops before the reasoning call). Active hours: **every day**, the span of the work blocks in `.claude/agents/day-schedule.json` - 08:00-20:00 Pacific as of 2026-09-16 (no weekday gate - the owner works 7 days/week, set at onboarding 2026-07-07); `HEARTBEAT_ACTIVE_HOURS_START/END` in `.env` still override
- Daily reflection: `python .claude/scripts/memory_reflect.py [--date YYYY-MM-DD]` (defaults to yesterday)
- Notification test: `python .claude/scripts/notify.py`; guardrail test: `echo <text> | python .claude/scripts/guardrail.py`
- Agent teams: `python .claude/scripts/teams.py list|show <id>|validate`
- Daily run: `python .claude/scripts/agent_day.py [--dry-run] [--team <id>] [--window morning|evening|auto] [--produce-only|--drain-only] [--force]`. Pause everything by creating `.claude/data/state/PAUSED`.
- Security tests: `python .claude/scripts/tests/test_security.py` (command guard, subshell extraction, secret-file + Finance blocking, hooks end-to-end, localhost:port allow + subdomain-suffix block). Also `test_ledger.py` (66), `test_dispatch.py` (26), `test_teams.py` (34), `test_failover.py` (96 - backup routing: a private job never borrows a cloud provider, only capacity errors reroute, a spent window defers rather than fails).
- Heartbeat/reflection/notify logs: `.claude/data/logs/heartbeat.log`, `reflection.log`, `notify.log`
- Chat bot: REMOVED 2026-07-07 (Slack opted out).
- Dashboard: `npm run dev` then Home (heartbeat panel), `/drafts` (review + approve→Gmail), `/vault` (browse Memory/). Agent-layer bridge: `src/lib/services/secondbrain.ts`; draft-action API: `src/app/api/secondbrain/draft/route.ts` (spawns query.py via SECONDBRAIN_PYTHON, defaults to miniconda). (API-credits panel removed 2026-07-07.)
- Scheduler: **on-demand by default** - `setup_scheduler.ps1` registers NO tasks unless given `-EnableDailyRun` / `-EnableSlackMonitor` / `-EnableHeartbeat` / `-EnableReflection` / `-EnableWiki`. **`-EnableDailyRun`** is the agent-team automation (`agent_day.py` at 05:00 and 21:30, one action + two triggers, `--window auto` picking the half by clock) and also registers `SecondBrain-AdminCheck` every two hours from 08:00 through 20:00. **Every hour it registers comes from `.claude/agents/day-schedule.json` (2026-09-16)** - the script reads the `automation` section rather than carrying its own copy, and `test_day_schedule.py` asserts it hard-codes no `-At`. It supersedes `-EnableHeartbeat`/`-EnableReflection` - do not enable those alongside it. Admin scans Gmail plus all new one-to-one Slack DMs. **`-EnableSlackMonitor`** is the same read-only DM intake on a shorter hourly 08:00-20:00 loop (the work blocks): unanswered DM bursts that could need their input are queued for a draft (acknowledgement-only bursts are skipped deterministically, and `draft.reply` applies the 2026-08-27 bar below), and unanswered actionable requests also create an idempotent Prisma task — scheduled for Today with a desktop toast when a concrete request was extracted or the sender is their PI, else a **quiet low-priority undated backlog task with no toast**, because replying on Slack is not itself a high-priority task and the reply lives in the draft (the owner, 2026-08-31); a later message from the owner closes the preceding incoming burst without creating either. It never posts to Slack and makes no model call itself. The daily run spends no API credit because both cloud runtimes use their subscription CLIs. Manual scanning remains available through the dashboard or `/draft-replies`. (`-Status` / `-Remove`; log at `.claude/data/logs/scheduler.log`.) See docs/DEPLOYMENT.md
