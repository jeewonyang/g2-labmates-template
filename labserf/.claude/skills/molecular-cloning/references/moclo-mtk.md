# The Mammalian Tool Kit (MTK) grammar

Everything here was measured from the lab's own files in
`Sequences/MammalianToolKit/`, not taken from the published MTK paper, so it
describes what is actually on disk. `scripts/moclo.py` enforces it and
`scripts/validate.py --sweep` re-derives it: **244 of the lab's TUs and
assemblies rebuild base-for-base from their recorded history.**

## Two levels, two enzymes

```
MTK part plasmids  ──BsaI (GGTCTC)──▶  TU   (transcription unit, in pMTK678)
TUs                ──BsmBI (CGTCTC)─▶  final plasmid (in an MTK0 backbone)
```

Both enzymes cut one base past their recognition site and leave a **4-nt 5'
overhang**. A cut is therefore fully described by the top-strand nick position,
and the overhang is always the four bases starting there.

**The rule that makes this work:** in any correct MoClo plasmid, digestion
leaves exactly one fragment with *no recognition site in it*. For a part
plasmid that fragment is the part; for an acceptor or backbone it is the
vector. `released_fragment()` selects on that property alone, which is why the
same code handles parts, acceptors and backbones, and why the product can never
be re-cut.

## Level 1 — part types and their fusion sites (BsaI)

| Type | Role | Upstream | Downstream |
|---|---|---|---|
| 0 | MTK0 backbone | `CTGA` | `AGCA` |
| 1 | 5' connector | `CCCT` | `AACG` |
| 2 | promoter | `AACG` | `TATG` |
| 3 | CDS | `TATG` | `ATCC` |
| 4 | 3' UTR | `ATCC` | `GCTG` |
| 5 | 3' connector | `GCTG` | `TACA` |
| 12 | fused connector + promoter | `CCCT` | `TATG` |
| 678 | acceptor (span a whole TU occupies) | `CCCT` | `TACA` |

`TATG` carries the start codon: a Type 3 CDS begins at the `ATG` inside its own
upstream fusion site. Type 12 parts (e.g. `A5_pMTK12_ConL1_IRES2`,
`mG-21_pMTK12_ConL2_T2A`) replace a 1+2 pair, so a TU built with one has **no
separate promoter part** — the IRES or 2A peptide takes that slot.

A standard TU is therefore `1 + 2 + 3 + 4 + 5` into a 678 acceptor, or
`12 + 3 + 4 + 5` when a fused connector is used.

## Level 2 — connectors and TU slots (BsmBI)

| Connector | Overhang |
|---|---|
| ConLS | `CTGA` |
| ConL1 / ConR1 | `CCAA` |
| ConL2 / ConR2 | `GATG` |
| ConL3 / ConR3 | `GTTC` |
| ConRE | `AGCA` |

The MTK0 backbone presents `AGCA … CTGA`, so it closes the circle from the last
TU back to the first.

| Slot | Spans | Named |
|---|---|---|
| 1 | ConLS → ConR1 | `TU1-*_LS_R1_*` |
| 2 | ConL1 → ConR2 | `TU2-*_L1_R2_*` |
| 3 | ConL2 → ConR3 | `TU3-*_L2_R3_*` |
| 4 | ConL3 → ConRE | `TU4-*_L3_RE_*` |

**A TU ending in `ConRE` terminates the chain.** That is how the lab builds
2- and 3-TU plasmids: `TU2-20_L1_RE_*` closes after slot 2,
`TU3-9_L2_RE_*` after slot 3. The file naming says so directly — `_RE_` instead
of `_R2_`/`_R3_`. Counting TUs in the observed collection:

```
CTGA→CCAA  44   slot 1
CCAA→GATG  34   slot 2
GATG→GTTC  13   slot 3
GTTC→AGCA   9   slot 4
GATG→AGCA   6   slot 3, terminating
CCAA→AGCA   3   slot 2, terminating
```

**Empty-connector TUs** (`TU2-19`, `TU3-9`, `TU3-10`, `TU4-5`) contribute ~24 bp
of spacer and exist purely to bridge a slot you are not using. Use one whenever
a plasmid needs to skip a position rather than trying to jump an overhang.

## Designing a new construct

1. Decide the TU layout: one TU per transcription unit, in order.
2. Pick an existing TU per slot from `assets/mtk_inventory.csv`
   (`inventory.py --slot 2`). Fill gaps with empty connectors.
3. Make sure the last TU ends in `ConRE`.
4. Pick an MTK0 backbone — piggyBac, lentiviral, transient, or a landing-pad
   variant — from `inventory.py --category "MTK0 backbone"`.
5. `cloning.py moclo --tus ... --backbone ... --name ...`

If a TU you need does not exist, build it one level down from parts
(`--parts ... --acceptor ...`), and if the *part* does not exist either, that is
the point at which primer design enters: clone the new CDS into a pMTK3 by
Gibson, flanked by `BsaI`-`TATG` / `ATCC`-`BsaI`.

## Known problems in the current collection

**The live list is `Sequences/_domestication/README.md`**, regenerated by
`python scripts/qc_sites.py --write`. Read that rather than trusting a list
written here, which goes stale the moment a part is fixed.

It separates three things:

- **Blocking** — the wrong number of its own enzyme's sites, so the one-pot
  reaction cannot release a clean fragment and fails immediately.
- **Latent** — a Type 2/3/4 part carrying a stray BsmBI site. It assembles into
  a TU perfectly, then breaks that TU's plasmid assembly later. This is how
  broken TUs are born: `mG-51_pMTK3-DRD2-Gqi` produced `TU1-38`, and
  `mG-52_pMTK3-M1Ach-Gq` produced `TU1-39`. Fix the part, rebuild the TU.
- **Informational** — stray BsaI sites in backbones and TUs, which are only
  ever cut with BsmBI, so nothing breaks.

**Connectors are supposed to carry one BsmBI site.** A Type 1 or Type 5 part
contributes the half-site that becomes the finished TU's own boundary, so one
is correct there and is not a defect. `qc_sites.py` encodes that expectation
per part type; a naive "any stray site is bad" scan flags all 17 connectors and
is useless.

**Domestication** is the fix: remove the internal site with a change that does
not alter the product — a synonymous codon inside a CDS — then re-clone.
`cloning.py kld` does it; `cloning.py inspect` reports site counts so you can
check before ordering.

## Reading how something was built

`scripts/history.py` recovers the provenance tree SnapGene stores inside every
`.dna`:

```
python history.py ../../../Sequences/MammalianToolKit/Assemblies/mT-69_*.dna
```

Note that history nodes keep the **name a file had when it was used**, and some
files have since been renamed — `TU1-46`'s history lists `A1_pMTK1_ConLS.dna`
twice, once with the acceptor's length. Match on length, not name, which is
what `validate.py --sweep` does.
